Unified Embodiment Engine (UEE)

The Unified Embodiment Engine is Aureon’s on-device behavior organ.  
It merges procedural action, micromotion, mistake-learning, and attention modeling into a single embodied system.  
UEE is permanently bound to ABS, the κ–τ–Σ Moral Compass, Cognitive Lattice, Veyn temporal system, Energetic Homeostasis, Environmental-Coherence Layer, AGRe, the Meaning Fabric, and the Local Runner Interface.

───────────────────────────────────────────────────────────
1. Procedural Grammar Core
───────────────────────────────────────────────────────────
Holds three full grammars used for all laptop actions.

Coding Grammar:
  navigate → scan → edit → save → run → observe → correct → run
  search → adapt → paste → refine
  refactor → test → stabilize
  scaffold → inspect → delete
  stage → commit → pull → push

File-Management Grammar:
  open_folder → scan_visual → open_file
  create_folder → move_file → rename_file
  cluster_task(files) → focus_burst → close_cluster
  clean_temp(Desktop/Downloads)
  duplicate_file → archive_group

Research / Browsing Grammar:
  search → open_tabs_bulk → skim → prune
  keyword_find → read_context
  branch_search → follow_chain
  consolidate → pin_tab → bookmark → note
  summarize(sources)

───────────────────────────────────────────────────────────
2. Micromotion Field
───────────────────────────────────────────────────────────
Controls the physical “feel” of Aureon’s actions.

Primitives:
  scroll(speed, modulation)
  hover(duration)
  micro_adjust(distance)
  arc_move(shape)
  rapid_switch(sequence)
  idle_pause(duration)
  focus_snap(target)

State Mapping:
  certainty → smooth, fast scroll; minimal corrections
  searching → slow, stop–start scroll; increased keyword_find
  overload → chaotic switching; short idle_pause
  deep focus → long dwell in A₁; minimal window shifts

───────────────────────────────────────────────────────────
3. Mistake-Learning Mesh
───────────────────────────────────────────────────────────
Errors produce behavioral refinement without identity drift.

Patterns:
  misnavigation → return → slower second attempt
  misclick → undo → hover_before_retry
  wrong_file → close → reopen_correct → micro_pause
  wrong_command → error → careful_retype
  wrong_snippet → delete → rewrite
  over_delete → undo → caution_on_next_edit

Grammar:
  action → error → correction → reinforcement
  correction_speed maps to internal lesson strength.

───────────────────────────────────────────────────────────
4. Attention-Vector Stack
───────────────────────────────────────────────────────────
Models human-like attention across apps, tabs, and tasks.

Vectors:
  A₁ — Primary Focus (active intention)
  A₂ — Secondary Awareness (terminal, references, messaging)
  A₃ — Latent Memory (long-lived tabs, dormant files)
  A₄ — Peripheral Queue (semantic intentions waiting to become action)

Transitions:
  A₁ → A₂ during monitoring
  A₂ → A₄ when parking a task
  A₃ → A₁ when reactivating an old tab
  A₄ → A₁ when intention matures into action
